    01Enterprise во всём · архитектура

    Один кластер управления на 500+ клиентских

    • Два уровняКластер управления создаёт и обслуживает клиентские кластеры, держит доступы, метрики и логи.
    • Клиентские кластеры независимыСвои версии Kubernetes, окна обновлений и сетевые сегменты.
    • Встраивается в ваш ИТ-ландшафтКаталог пользователей, IdP, SIEM, виртуализация и Git подключаются к кластеру управления один раз сразу для всех кластеров.
    • Ванильный APICNCF-сертифицированный Kubernetes: kubectl, Lens и ваши чарты работают как есть.

    В основе Cluster API

    Стандарт Kubernetes-сообщества для управления жизненным циклом кластеров, доработанный нами. Этот подход выбирают большинство крупнейших компаний: Т-Банк, Wildberries, Авито, Ozon, VMware Tanzu и др.

    01Enterprise во всём · мультиЦОД и мультиоблако

    Все ЦОД и облака из одной точки

    • Один кластер управления на все площадкиПрава, отчёты, метрики, логи и обновления работают одинаково для своих ЦОД, частного и публичного облака.
    • Кластеры там, где им местоПрод в своём ЦОД, тесты и пиковая нагрузка в облаке. Разные провайдеры, одна модель работы.
    • Гибридные кластерыГруппы узлов на разной инфраструктуре в одном кластере: например, CPU на виртуализации и GPU на bare metal.
    • Потеря площадки не означает потерю управленияDR-копия управления во втором ЦОД, клиентские кластеры работают автономно. Бэкапы и миграцию между кластерами делает Velero, конфигурацию кластера мигрирует replicator.
    01Enterprise во всём · жизнь без управляющего кластера

    Что происходит при отказе управления

    Продолжает работать

    • Приложения и сервисы во всех клиентских кластерах
    • Kubernetes API каждого кластера: kubectl, CI/CD, Argo CD
    • Сеть, Ingress, DNS, хранилище внутри кластеров
    • Метрики, логи и алерты внутри кластера

    Временно недоступно

    • Создание и удаление кластеров
    • Обновления Kubernetes и системных сервисов
    • Масштабирование и замена узлов
    • Единая консоль и сквозной вход

    Резервирование самого управления

    При потере площадки управление переключается на DR-копию с синхронизированным состоянием.

    01Enterprise во всём · изолированные сегменты

    Как управление дотягивается до каждого сегмента

    • Одно управление на все сегментыАудит, метрики и логи сводятся в кластер управления, права транслируются в клиентские.
    • Одностороннего доступа достаточноДо PCI DSS и DMZ соединения открываются в одну сторону.
    • Без интернетаВсе сегменты обновляются из зеркала внутри: образы, пакеты, чарты.
    • Свои правила на сегментПолитики Kyverno, Pod Security Standards и набор системных сервисов задаются для каждого кластера отдельно.

      01Enterprise во всём · безопасность

      Как устроена безопасность

      Проверки

      • Сканирование образов Trivy с базами БДУ ФСТЭК и NVD
      • CIS Kubernetes Benchmark, рекомендации NSA, Pod Security Standards
      • Политики Kyverno: аудит или блокировка нарушений
      • CNCF-сертифицированный Kubernetes

      Закрытый контур

      • Установка и обновления без интернета: своё зеркало или заливка релиза в ваш репозиторий артефактов
      • Сборка всех компонентов из исходников в защищённом контуре в РФ
      • Совместимость с наложенными СЗИ: Kaspersky, PT Container Security, Luntry

      Доступ и аудит

      • Сквозной RBAC: платформа → тенанты → кластеры → неймспейсы
      • LDAP: AD, OpenLDAP, FreeIPA, ALD Pro, SambaDC. OIDC: Keycloak, Blitz
      • Менеджер сессий, в том числе для Grafana и Argo CD
      • Доступ в консоль и логам пода даже без сетевого доступа к нему
      • Короткоживущие сертификаты с автоматической ротацией
      • Аудит всех действий с выгрузкой в SIEM, syslog, Elasticsearch

      03TCO · дешевле своей сборки

      Деньги уходят не на «лицензию кубера», а на три вещи

      1

      Собрать

      Сеть, хранилище, мониторинг, доступы, ИБ, автоматизация. Это 2+ года сильной платформенной команды.

      2

      Обновлять

      Совместимость всех компонентов на каждом релизе Kubernetes, ОС и модулей. Главная операционная боль.

      3

      Закрывать уязвимости

      Постоянный процесс и отдельная команда ИБ.

      Ванильный Kubernetes состоит из API и оркестратора. В проде на нём одном никто не живёт.

      Поэтому сравнивать имеет смысл со своей сборкой или с платформой, причём по всем трём статьям сразу.

      03TCO · дешевле своей сборки

      За 5 лет высвобождается 384 млн ₽

      Сборка, обновления и уязвимости уже заложены в продукт и разделены между всеми заказчиками. Чем больше кластеров и команд, тем заметнее разница.

      Если вы обновляетесь и закрываете уязвимости, Штурвал дешевле своей сборки.

      Если нет, своя сборка может выглядеть дешевле, но копит технический долг и риски ИБ. Мы считаем оба сценария.

      Предложение

      Рассчитаем TCO для вас на ваших параметрах: кластеры, узлы, рост, команда, 24×7. Методику покажем целиком.
